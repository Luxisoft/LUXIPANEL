# Vistas internas de módulos — 2026-09-30

Los 26 módulos web se montan como vistas React locales con carga diferida. Las rutas Astro conservan los enlaces directos y usan el mismo host. Los datos llegan por APIs JSON; no se navega un documento HTML para abrir o cerrar un módulo. Los iframes quedan limitados a documentos de correo y vistas externas aisladas.

`InternalModuleHost` conserva las vistas visitadas, formularios y scroll durante la sesión del servidor. Cerrar oculta la vista inmediatamente, cambia el historial local y aborta lecturas pendientes. `controller-scope` acota DOM, eventos, timers y conexiones de los controladores heredados. Ocultar pausa sondeos; cambiar de servidor o cerrar sesión dispone las vistas. Terminal y llamadas tienen servicios independientes de esta visibilidad. Los menús de ajustes usan los diálogos de la vista montada.

App y desktop mantienen un registro equivalente por servidor y sesión autenticada. Mensajería y Preferencias son pantallas nativas. El SSE de mensajería se comparte entre vistas, llamadas y notificaciones. Las llamadas de audio y traducción usan Tolqia 1.2.0, empaquetado en `LP-LICENSE-SERVER/vendor/tolqia`; en móvil el PCM se captura y reproduce con `react-native-audio-api`. Las notificaciones siguen los permisos del sistema. No se ha añadido recepción de llamadas con la aplicación terminada.

El registro nativo de passkeys abre una página pública limitada a una ceremonia de alta. Un grant opaco de un solo uso expira en 60 segundos; la ceremonia expira en 120 segundos. El fragmento se elimina antes de leer las opciones. No se entrega un JWT en la URL. Se mantienen el RP, origen y verificador WebAuthn existentes. El resultado se consulta con la sesión del dueño. Las contraseñas siguen gestionadas externamente. El historial de seguridad personal filtra estrictamente el usuario autenticado.

Validación: 521 pruebas de app y 216 de desktop; pruebas de lifecycle web y de alta de passkey, incluido autenticador virtual Chromium y verificación criptográfica real. La prueba de navegador recorre los 26 módulos, conserva borradores y scroll, verifica ausencia de iframes de módulo y de navegación al cerrar, y comprueba continuidad del transporte de terminal simulado. Los cierres locales medidos quedaron por debajo de 60 ms. También pasaron navegación atrás/adelante y la carga de Preferencias en los 12 idiomas. Las APIs de las pruebas de navegador son fixtures; no sustituyen una prueba de todas las operaciones sobre servidores reales.

Se generan builds SSR web, renderer desktop y bundles Expo Android/iOS. La configuración Android incluye permisos de micrófono y servicio en primer plano. No hay SDK Android ni Xcode disponibles para generar aquí los binarios nativos. Audio, interrupciones y comportamiento de segundo plano necesitan prueba en dispositivos físicos. El servicio local del grafo no estaba disponible: se comprobó su estado de error recuperable, no las operaciones reales de indexado.

El generador de migración fue una herramienta temporal; las vistas ya convertidas son el código que se mantiene. Para añadir módulos, registrar componente y namespaces en `module-registry`, declarar controles dentro del root y disponer recursos mediante el scope. Mantener el fondo continuo del body y respetar reduced motion.
